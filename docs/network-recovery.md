# 2.1.10：网络恢复与流量策略（Issue #15）

## Windows

桌面模式使用物理网卡的 DNS，由 TUN 拦截运行期间的查询；不再把网卡 DNS 设为 `127.0.0.1`，也不占用第三方本地 DNS 的 53 端口。严格模式在物理接口没有全球 IPv6 地址时保持系统网络，保留启用意图并等待网络恢复。

快照使用同卷原子替换，分别记录 IPv4、IPv6 DNS 的自动/手动状态。恢复以接口 GUID 定位，对仍属于本程序的地址族逐项还原；后续用户修改的配置予以保留。

旧快照或遗留 DNS 指向本机时，只有同一网卡的 DHCP DNS 证据能够证明可恢复配置，才迁移到自动 DNS。缺少证据时保留快照并报出需要手动恢复的原因，不猜测静态 DNS。网卡暂时不可用、快照损坏或 DNS 恢复失败时，仍独立执行核心停止、专属路由和防火墙清理；保留待恢复快照，后续守护重试。

守护根据物理网卡地址、默认网关和 DNS 的变化重建核心。桌面启用增加实际 HTTPS 转发验证，失败则回滚；日志记录 PowerShell 调用栈以及服务 watch/stop 错误。

状态查询无需等待配置操作锁。互斥的配置请求立即返回繁忙，桌面显示等待状态并作有限重试；不再把排队时间混入同一次 IPC 的执行期限。服务关闭期间拒绝新的变更请求，并向 Windows 报告清理进度。

## macOS

继续保留真实 DNS，拒绝把本机解析器保存成新原始快照。旧快照有污染或网络服务不可用时，继续清理核心及本程序 PF 规则，保留待恢复信息。启动失败和核心异常会先恢复系统网络，再按有限冷却时间重试；手动暂停保持暂停。

保留本机未发布 2.1.8 的代理兼容修复：支持 IPv6 回环代理，保留已启用的本机代理设置，不把回环协议标记成公网出口协议。桌面会提示更新旧后台，更新时保留暂停状态。

## Android

VPN 使用独立 DNS 作用域，不修改物理网卡 DNS。核心故障关闭 TUN、恢复系统路由，保留用户启用意图并在 30 秒后重试。即使仍是同一 Network，地址、路由或回退策略变化也会重建核心。授权撤销、显式停止仍会停止服务。

## 可选 IPv4 回退

三端默认继续严格 IPv6。桌面网络概览和 Android 启动方式卡片提供“IPv6 失败时允许 IPv4 回退”开关；更改运行中的策略会重新连接。

开启后，TCP 先尝试 IPv6（包括现有的补充 AAAA 节点），失败才尝试 IPv4。UDP 继续遵守首包重放约束，允许有重复处理机制的 QUIC/NTP 在建立流时回退；任意无响应 UDP 数据报不会因为开启回退而跨地址重放。解析失败不等同于没有 AAAA，也不会因此直接放行 IPv4。回退连接的原因记录为 `ipv6_failed_fallback`；桌面连接表显示“IPv4 回退”。开启回退可能产生 IPv4 计费流量。

命令行可使用 `v6core --allow-ipv4-fallback`，移动核心配置对应 `allow_ipv4_fallback: true`。诊断与健康接口报告实际策略。

## 验证边界

使用模拟系统 API 的回归测试覆盖 DNS 污染、混合地址族、用户后续修改、接口消失、快照损坏及独立清理。Go 测试覆盖严格默认、TCP/UDP 显式回退、DNS 失败和取消；桌面测试覆盖暂时查询失败、缺失服务和策略操作。GitHub Actions 另行运行一次性 Windows VM 的真实 Wintun/MSI 和 Android 模拟器的 VPN/网络恢复测试。

这些测试不能替代特定校园网络的下一次真实开机、睡眠唤醒，以及哔哩哔哩/虎牙客户端登录和播放验证。Issue 中最初正确快照丢失的原因仍未确认，不把全部现场联网故障归为同一个原因。

## Windows 实机补充验证

2.1.10 修正启动检查对单个微软站点的依赖。Windows 的物理网卡预检和接管后检查、macOS 的接管后检查均使用独立 HTTPS 站点：任一站点完成经过证书验证的请求即通过，全部失败仍恢复原网络。切换检测站点不会放宽 IPv6 策略。Android 使用 VPN 内数据路径握手，不依赖这一外部站点检查。

Windows 2.1.6 实机上复现 B 站直连 TLS 失败、Airport 代理成功；升级后系统 DNS 保持校园 DHCP，B 站直连恢复。V6Only 不改写 Windows 系统代理：退出 Airport 后若系统代理仍指向未监听的 127.0.0.1:7890，需要关闭该代理或重新启动 Airport。

## Windows 2.1.11 覆盖升级实测（2026-10-18）

在 Windows 11 x64 实机上，通过 SSH 将 2.1.10 MSI 覆盖升级到 2.1.11。安装前核对发布包的 SHA256，停止后台服务后备份应用文件、配置和完整流量数据库；安装沿用原目录，MSI 返回成功码 0。

升级后确认：

- V6Only 服务自动启动，转发恢复，核心报告 `ready=true`、`data_path_verified=true`。
- 严格 IPv6 策略保留，`allow_ipv4_fallback=false`；物理网卡 DNS 保持原校园 DNS。
- 流量记录的起始时间未变，IPv4/IPv6 上传、下载累计值均未减少。
- B 站首页通过 IPv6 完成 HTTPS 请求并返回 HTTP 200，连接表记录了实际 IPv6 远端地址及双向字节数。
- 桌面界面在原交互会话中重新启动，临时升级任务已移除。

站点可达性仍有波动：本次 B 站启动检查曾超时，随后直接 HTTPS 测试成功；微软官网的一次 HTTPS 测试出现 TLS 握手失败。以上结果验证本次覆盖升级及恢复过程，不代表所有站点、开机或睡眠唤醒场景均已通过。
